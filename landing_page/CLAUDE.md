# keril.art — личный лендинг (визитка)

## Что это
Одностраничный сайт-визитка для keril.art. Фронтенд находится в
`index.html`: CSS в одном блоке `<style>`, скрипт в одном `<script>`, без
сборщиков и фреймворков, без инлайн-атрибутов `style=""`. PHP endpoint
`counter.php` считает посещения и пишет журнал; для счётчика на сервере
нужны nginx и PHP-FPM. Список репозиториев на странице "Проекты" браузер
берёт прямо из GitHub API (см. ниже), серверная часть для этого не нужна.

В будущем на поддоменах появятся отдельные страницы пет-проектов —
это отдельные одностраничники, никак не завязанные на этот файл.

## Эстетика (держаться этого стиля при любых правках)
Тематика сайта: **Frutiger Aero**, **Tenshi Kawaii** и **Windows XP**.
Глянец и стекло, небо и холмы Windows XP, пастельная «ангельская» милота (звёздочки,
сердечки, розовые акценты) и интерфейс в духе XP Luna (окна с
тайтл-барами, выпуклые кнопки). Не уводить в другие темы (море/пляж,
плоский минимализм, киберпанк-неон и т.п.).

"Cyber Frutiger Aero" — глянцевый Y2K/Windows-XP-era стиль:
- глянцевые выпуклые кнопки в духе Windows XP Luna (градиент светлый→синий,
  белый блик сверху): `.xp-button`, `.language-toggle`, `.route-home`,
  маленькие квадратные кнопки-ссылки с иконкой `.link-button`
- фон — фиксированный слой `.scene` на весь экран: пейзаж в духе обоев Bliss
  из Windows XP (по просьбе владельца). Нарисован вектором, фотография Bliss
  не используется (она чужая). Слои снизу вверх: небо (градиент `--sky`
  на самой `.scene`), четыре облака `.scene__cloud` (редкие, inline SVG),
  затем `svg.scene__hills`: две далёкие гряды гор справа, зелёный холм с
  пятнами света и тени (radial-градиенты), передний луг, клинья тропинки и
  жёлтые цветочки. Облака плывут за холмом слева направо. Светлая тема —
  светлое дневное небо, тёмная — ночное небо и тёмный холм; цвета — только
  в переменных `--sky`, `--cloud-*`, `--mountain*`, `--hill-*`, `--field-*`,
  `--dirt`, `--flowers`, `--grass-opacity` (две строки: `:root` и
  `html[data-theme="dark"]`), градиенты берут их через классы на `<stop>`.
  Холм масштабируется `preserveAspectRatio="xMidYMax slice"`: на узких
  экранах видна его середина, на широких обрезается верх неба.
  Облака: `@keyframes cloud-drift` двигает их только `transform` (GPU-слои,
  `will-change`), скрипт на каждый кадр не работает; длительность своя у
  каждого, 170–290с (крупные быстрее, ~10–20 px/с на широком экране),
  отрицательный `animation-delay` расставляет их по небу с первой секунды.
  Края пухлые благодаря SVG-фильтру `#cloud-soft` (шум + смещение + размытие).
  Трава — маленькая плитка шума `#grass-texture` (data URI в `<pattern>`,
  рисуется один раз и повторяется), полноэкранных фильтров нет намеренно.
  При `prefers-reduced-motion` облака стоят на месте (`animation-play-state:
  paused`, а не `none`, чтобы не съехались к левому краю).
  **Разметка и правила фона продублированы в `404.html`** (она самодостаточна);
  при правке менять в обоих файлах.
  Владелец попросил убрать прежний фон и всю пасхалку: узор точек, canvas с
  фигурами и волнами за курсором, лопание фигур, комбо, окно "пузыри.exe",
  Tenshi-tan с переключателем и окошком "tenshi.exe" — их больше нет.
- счётчик посетителей — маленькое XP-окошко `#visitors.counter-window`
  ("посетители.exe") в конце `#home-details`
- все окна в одном дизайне — общие классы `.xp-window`, `.xp-window__bar`,
  `.xp-window__title`, `.xp-window__button`, `.xp-window__body`; инлайн-стилей
  у окон нет. Окна главной (`#about`, `#projects`, `#visitors`) и окна
  страниц `#page=…` получают три рабочие кнопки (`addWindowButtons`,
  обработчик кликов по `[data-window-action]`): "свернуть" схлопывает окно
  до заголовка (`.is-minimized`), повторно — разворачивает; "на весь экран"
  ведёт на страницу окна (`data-window-page`), а на самой странице —
  обратно на главную; "закрыть" спокойно гасит окно, как в Windows
  (`.is-closing`: за 0,2с слегка уменьшается и тает), место остаётся,
  через 2с (`windowReturnDelay`) окно так же спокойно возвращается
  (`.is-returning`). **Пузырей на сайте нет нигде** — ни лопания окон,
  ни брызг, ни колечек, ни пружинящих "хлопков": владелец попросил убрать
  их совсем (18.11.2026), не возвращать. У окна "посетители" кнопка
  "на весь экран" никуда не переводит: окно прямо на главной расширяется
  до ширины остальных окон (`.is-expanded`) и вместо строки-сводки
  показывает статистику за всё время, год и месяц
  (`#visitor-stats-panel`); повторное нажатие сжимает его обратно
- в конце основной колонки `footer.page-footer`, в нём `.signature` — авторская подпись
  "made by Keril³" (тройка — `<sup>`, одного размера с "made by"), белая с
  тёмной тенью, между двумя мерцающими розовыми звёздочками; отступ 32px
  как у остальных блоков. Не удалять и не менять текст
- масштаб: интерфейс растёт вместе с шириной окна. Скрипт в `<head>`
  (`updateUiScale`, вызывается и на resize) ставит `--ui-scale` =
  1 + (ширина окна / 1280 − 1) / 4, не меньше 1 и не больше 1.25 — растёт
  вчетверо медленнее окна (1920px — ~1.13×, 2000px — 1.14×, 2560px и шире —
  1.25×; уже 1280px масштаб 1, мобильная вёрстка не меняется). Владелец
  дважды просил уменьшить: "ширина / 1280, до 2×" и "вдвое медленнее, до
  1.5×" были слишком крупными. Ширина колонки окон — `--column-width`
  (936px, на 20% шире прежних 780px по просьбе владельца); до неё же
  расширяется окно "посетители" (`.is-expanded`). CSS
  `zoom:var(--ui-scale)` стоит на `.page-column` и плавающих окнах
  (`.xp-popup` — баннер cookie):
  растёт всё, текст в окнах тоже. Фон не масштабируется. Внутри элемента с
  `zoom` `translate()` и `vw`/`vh` тоже умножаются на масштаб, а
  `getBoundingClientRect()` отдаёт уже увеличенные размеры (`clientWidth` —
  без увеличения) — это важно для любых расчётов позиций. Новые
  фиксированные окна добавлять в тот же список с `zoom`
- светлая и тёмная (ночь) темы: `html[data-theme="light"|"dark"]`,
  выбор хранится в `localStorage` (`keril-art-theme`), кнопка `#theme-toggle`
  в верхней панели. Скрипт в `<head>` ставит тему до отрисовки. Пока
  посетитель сам не нажал эту кнопку, сайт берёт тему из настроек системы
  (`prefers-color-scheme`) и следит за ней, пока страница открыта
  (`systemDarkTheme`, `themeChosen`). Окна выбора темы при первом заходе
  ("выбор_темы.exe", `#theme-gate`) больше нет: владелец убрал его в
  ноябре 2026, чтобы работодатель сразу видел сайт, а не диалог.
  Цвет панели браузера на телефоне — одна `<meta name="theme-color">`,
  верх неба текущей темы: `#4A9BEB` днём, `#050A22` ночью (`themeColors`).
  Ставит её скрипт в `<head>` (`setThemeColor`) до отрисовки и
  `applyTheme` при каждой смене темы; в `404.html` — её скрипт в `<head>`.
  Две `meta` с `media="(prefers-color-scheme…)"` не годятся: тему можно
  выбрать вручную. При смене цветов неба поменять и эти два значения.
  Тёмная тема — блок правил `html[data-theme="dark"]`
  в CSS; окна перекрашиваются через классы `.xp-window`, `.xp-window__bar`,
  `.xp-window__body`. Цвета фона — переменные, см. выше.
  Новые блоки должны выглядеть нормально в обеих темах
- полоса прокрутки: тонкая глянцевая в стиле XP (12px, голубой бегунок, в
  тёмной теме — сине-фиолетовый), раньше была полностью скрыта, и на
  ноутбуке не было видно, что текст продолжается ниже. Chromium/Safari
  рисуют её через `::-webkit-scrollbar` (стандартные `scrollbar-color` /
  `scrollbar-width` отключили бы эти правила, поэтому они только для
  Firefox, в `@supports not selector(::-webkit-scrollbar)`).
  `scrollbar-gutter:stable` держит место под полосой всегда, чтобы колонка
  не прыгала между страницами с прокруткой и без. На телефонах полосы
  поверх страницы, ничего не меняется
- клавиатура: всё функциональное доступно по Tab, фокус везде показан одним
  розовым контуром `outline:3px solid #FFC9E8` (`:focus-visible`; у поиска
  контур рисуется на `.status-bar` и только в клавиатурном режиме —
  класс `html.is-keyboard-nav` ставится по Tab и снимается любым нажатием
  мыши/пальца). Tab закрывает открытые подсказки поиска и меню языка.
  Первый Tab показывает ссылку «К содержимому» / «Skip to content»
  (`.skip-link`, `skipLink`, первый элемент `.page-shell`, спрятана над
  окном, пока на ней нет фокуса): Enter переводит фокус на
  `main#main` (`tabindex="-1"`), минуя поиск, тему, язык и меню.
  Переход делает скрипт (`preventDefault` + `focus()`), а не якорь
  `#main`: иначе сменился бы адрес `#page=…` и маршрут сбросился бы
  на главную. Без JS ссылка работает как обычный якорь.
  Новые кнопки и ссылки должны получать
  этот же контур, без синих/своих вариантов. После закрытия окна с
  клавиатуры фокус возвращается на его кнопку, после "на весь экран" —
  на кнопку окна открывшейся страницы
- шрифт: `Monocraft` с поддержкой кириллицы; bitmap-пиксельная подача
  для интерфейса и заголовков
- никаких готовых UI-библиотек, никакого Bootstrap/Tailwind — только
  руками написанный CSS, чтобы сохранять именно этот неповторимый вид

## Цветовая палитра
```
skyDay     #4A9BEB → #E6F5FD  дневное небо (верх → горизонт), см. --sky
skyNight   #050A22 → #2A3E6E  ночное небо
hill       #8CC63F → #3F8F1F  дневной холм (вершина → низ), см. --hill-*
accent     #4FA8E8   основной голубой акцент (бордеры, иконки)
accentDark #1C5FC4   тёмный акцент (хедеры окон, обводки)
glow       #CFEBFF   светлый акцент (градиенты, подсветка)
deep/ink   #0B2545   задуман для текста; сейчас текст чёрный (см. ниже)
kawaii     #FFC9E8   розовый акцент (звёздочки, сердечко, контур фокуса)
```
Цвета вписаны как hex в блок `<style>` (переменные — только у фона, см. выше);
поменять цвет везде можно find-and-replace по hex.

Важно про цвет текста: правило `body,body *{color:#000000!important}`
(и `html[data-theme="dark"] body *{color:#E3EEFF!important}` в тёмной теме)
делает весь текст и `currentColor` в SVG чёрным (светло-голубым), поэтому
`color` без `!important` ни на что не влияет. Если элементу нужен свой цвет,
пиши его с `!important`, а для тёмной темы — отдельным правилом с
`html[data-theme="dark"]` (как у `.window-title`, `.route-home`, `.link-button`).

## Структура страницы
- Разметка по ориентирам (для экранных читалок и поисковиков, проверено
  axe без нарушений): `header.status-bar` (поиск, тема, язык),
  `nav.dock` (`aria-label` — `navLabel`), `main.page-main` (приветствие,
  страницы `#route-view`, окна главной `#home-details`; сохраняет отступ
  32px колонки), `footer.page-footer` (подпись и "настройки cookie").
  В `main` первым идёт невидимый `h1.visually-hidden` (`pageHeading`:
  "Кирилл (Keril³) — начинающий разработчик"), заголовки окон — `h2`
  (`.xp-window__title`, и в `createRouteWindow`), у баннера cookie —
  `span`. Печатающееся приветствие `aria-hidden`: смысл
  страницы читалке даёт `h1`. Поле поиска — `role="combobox"` (только с
  этой ролью у него допустим `aria-expanded`).
- `<head>`: заголовок вкладки на главной — `pageTitle` ("Кирилл Keril³ —
  keril.art"), на страницах — "<раздел> | keril.art"; при смене языка
  меняется. Там же `meta description`, `canonical` и Open Graph
  (`og:title`, `og:description` — превью ссылки в Telegram/Discord) на
  русском. Картинка превью — `og-image.jpg` (1200×630, 89 КБ, JPEG):
  настоящий фон сайта со светлой темой и XP-окно "keril.art" с надписью
  "Кирилл · Keril³ / начинающий разработчик · геймдев"; отрисована
  браузером из `index.html` с добавленным окном, плюс `og:image:*` и
  `twitter:card=summary_large_image` (Discord показывает крупную
  картинку). Telegram и Discord кэшируют превью: после замены картинки
  старое может держаться у них несколько дней.
  Если меняется текст "обо мне", сверить эти описания.
  Там же блок `<script type="application/ld+json">` (schema.org: `WebSite`
  — название сайта в выдаче поисковиков, и `Person` — имя, ник, ссылка на
  GitHub). Браузер его не выполняет, CSP на него не действует. Если
  меняются имя, ник или профили, обновить и его.
- Иконки: во вкладке — SVG-облачко прямо в `<link rel="icon">` (data URI);
  `/favicon.ico` (16, 32, 48 px, прозрачный фон) — для сервисов, которые
  запрашивают его сами (превью мессенджеров, Яндекс); `/apple-touch-icon.png`
  (180 px, облачко на дневном небе: телефоны кладут иконку на квадратную
  плитку) — ярлык на экране телефона. Оба файла нарисованы из того же
  облачка; при смене иконки перерисовать все три. В data URI иконки
  пробелы записаны как `%20` (пробел в адресе недопустим, валидатор
  считает это ошибкой) — так же и при правке.
- Строка пути и языковое меню вверху. Поиск по сайту (`#site-search`)
  подсказывает только существующие разделы (`searchItems`): страницы
  "Об этом", "Обо мне", "Проекты", "Связаться со мной" и ссылку на GitHub
  (у пункта с `url` подсказка открывает адрес в новой вкладке, значок —
  цепь, как у ссылок на странице контактов, тип "ссылка"). Подписи — ключи `suggest*Title`/`suggest*Detail` в
  `translations`, ключевые слова описывают содержимое окон на обоих
  языках (ищется по русским и английским подписям сразу). Когда появляется
  новый раздел или меняется текст окна, обновлять и этот список;
  несуществующие разделы туда не добавлять. Репозитории с GitHub
  добавляются в поиск сами (`getSearchItems`): тип "проект", значок —
  логотип GitHub, путь `C:\keril.art\projects\<имя>`, ищутся по имени,
  описанию, языку и topics; выбор открывает `#page=projects`, прокручивает
  к проекту, ставит на него фокус и на 1.6с подсвечивает розовым
  (`highlightRepo`). Список с GitHub начинает грузиться при фокусе поиска.
  Избранный проект из "проекты.zip" (SugarBridge) — свой пункт в
  `searchItems` с полем `project` (тип "проект", значок GitHub, путь
  `C:\keril.art\projects\sugarbridge`, ключевые слова на обоих языках);
  выбор открывает `#page=projects` и подсвечивает карточку
  (`highlightProject`), а репозиторий с тем же именем из GitHub в поиск
  второй раз не добавляется. Подсказки, в названии которых есть все слова
  запроса, идут первыми (стабильная сортировка), поэтому Enter по
  "sugarbridge" открывает проект, а не страницу "Проекты".
  Escape в поиске: первый закрывает подсказки, второй стирает текст.
- Навигационный dock открывает внутренние страницы в той же вкладке через
  маршруты `#page=about`, `#page=projects`, `#page=contact`; кнопки не
  скроллят к якорям и не открывают модальные окна. Browser Back/Forward
  переключает страницы. "об этом" (`#page=about`) — отдельное окно
  "об_этом.txt" про сам сайт: для чего он и зачем владелец этим
  занимается; его текст лежит в `<template id="about-site-content">`
  рядом с окнами главной. Окно главной "обо_мне.txt" (`#about`) — про
  владельца; его кнопка "на весь экран" открывает `#page=me`. Кнопка "github" — обычная ссылка на
  https://github.com/Keril3 в новой вкладке (внутренней страницы GitHub
  нет; старый адрес `#page=github` открывает главную).
- `404.html` — своя страница ошибки: XP-окно "ошибка_404.exe" с грустным
  облачком, ненайденным путём в стиле `C:\keril.art\...` и кнопкой на главную.
  Тот же фон, что на главной. Тема и язык берутся из выбора на сайте
  (`localStorage`), иначе из системы.
  Отдаётся nginx'ом по любому адресу, поэтому всё в ней встроено, а ссылки
  абсолютные (`/`). Для неё в server-блоке нужен `error_page 404 /404.html;`.
- Анимированное локализуемое приветствие: печатается по букве
  (`animateGreeting`). При `prefers-reduced-motion` оно появляется сразу
  целиком, а мигающий курсор поиска (`.caret`) стоит на месте — как и
  облака, звёздочки (`.twinkle`) и остальные анимации при этой настройке. Внутри `.hero-greeting`
  (это `display:grid`) два `span` в одной ячейке: `__typed` — печатаемый
  текст с курсором, `__full` — невидимая копия всей фразы, она с первой
  секунды держит итоговую высоту. Без неё на телефонах (там фраза в три
  строки) окна ниже прыгали на строку, когда печать доходила до третьей
  строки (CLS 0.058, теперь 0.001). Курсор — `::after` у обоих `span`

## Хостинг и деплой (keril.art)

### Как устроен сервер
С 11.11.2026 сайт на новом VPS: IP `94.242.59.197`, Ubuntu 26.04, nginx
1.28, PHP 8.5 (прежний сервер 195.135.253.220 стёрт и отменён). Домен на
Namecheap, A-записи `@`, `www`, `vpn` указывают на этот IP. На том же
сервере работает личный VPN владельца (3x-ui с Xray: VLESS+Reality,
Hysteria2, VLESS+TLS) и AdGuard Home; AmneziaWG больше нет. Их настройки
трогать нельзя. Сервером владелец занимается отдельно (вместе с Claude в
`E:\PersonalServer`); там же справка `SITE-SERVER-NOTES.md` — актуальное
описание nginx-конфига, кэша и проверок для этого сайта.

- Файлы сайта лежат в `/var/www/keril.art/`, раздаёт nginx.
- nginx слушает порт 80 (HTTP: проверка Let's Encrypt и переадресация на
  HTTPS) и `127.0.0.1:8444` (HTTPS, только внутри сервера,
  `ssl proxy_protocol`, `http2 on`).
- Порт 443/tcp занят Xray (Reality). В Reality-инбаунде dest =
  `127.0.0.1:8444`, SNI = `keril.art`, `www.keril.art`: обычные посетители
  на 443 пересылаются Xray на nginx, поэтому https://keril.art работает на
  обычном 443.
- Xray передаёт nginx настоящий IP посетителя через PROXY protocol, nginx
  его восстанавливает (`real_ip`), так что `$remote_addr` и лимиты по IP
  работают (на `counter.php` — 30 запросов в минуту с IP, всплеск до 20).
  Поэтому nginx на 8444 отбрасывает соединения без PROXY-заголовка:
  проверять его напрямую можно только с `curl --haproxy-protocol
  --resolve keril.art:8444:127.0.0.1 https://keril.art:8444/…`.
- Сертификаты Let's Encrypt выпускает certbot в режиме webroot
  (`-w /var/www/keril.art`): порт 80 занят nginx, standalone не работает.
- **Сертификат `keril.art` должен оставаться RSA.** keril.art — сайт, под
  который маскируется Reality: 13.11.2026 его перевыпустили как ECDSA, и
  Reality-клиенты 11 минут не могли подключиться (обрыв сразу после
  рукопожатия), пока не вернули RSA. В настройках продления certbot тип
  ключа закреплён (`key_type = rsa`); `vpn.keril.art` — ECDSA, это
  нормально. Не «улучшать» сертификат keril.art до ECDSA и не менять его
  тип ключа, не проверив Reality (`vpn-selftest` на сервере).

### Правила работы с сервером
- Готовую и проверенную правку ассистент сам, не спрашивая, коммитит,
  выкладывает на сайт и отправляет на GitHub (владелец разрешил это раз
  и навсегда в ноябре 2026). Выкладывает только через пользователя
  `keril-deploy`; под другими пользователями (`vpnuser` и т.д.) к серверу
  не подключаться.
- `counter.php`, nginx, сертификаты, секреты и всё остальное на сервере
  меняет только владелец.
- Не предлагать менять порты 80/443, настройки nginx, Xray или 3x-ui без
  явной просьбы.

### Выкладка
`index.html`, `404.html`, `robots.txt`, `monocraft.woff2`, `favicon.ico`,
`apple-touch-icon.png`, `og-image.jpg` и `.well-known/security.txt`
заливаются из PowerShell (ключ лежит в агенте
Windows), по одному файлу за вызов, перезапускать ничего не нужно, потом
результат проверяется на сайте (SHA256 живого файла = локального):
```powershell
scp -o BatchMode=yes index.html keril-deploy:/index.html
```
`keril-deploy` — пользователь только для SFTP, без командной строки и `sudo`,
заперт в `/var/www/keril.art` (`/etc/ssh/sshd_config.d/keril-deploy.conf`).
Папка принадлежит root, поэтому он может перезаписать эти файлы, но не
создать и не удалить файл: новый файл владелец сначала создаёт пустым
(`sudo install -o keril-deploy -g "$(stat -c %G index.html)" -m 644 /dev/null <файл>`
в `/var/www/keril.art`), а залить его содержимое может уже ассистент. Лимит файла 2 МБ
(`/etc/security/limits.d/keril-deploy.conf`). Ключ на компьютере владельца:
`~/.ssh/keril_deploy` с паролем, загружен в агент Windows; псевдоним
`keril-deploy` в `~/.ssh/config`. Отозвать доступ:
`sudo rm /home/keril-deploy/.ssh/authorized_keys`.

`counter.php` и новые файлы владелец копирует в `/var/www/keril.art/` сам.
На сервере один раз должны быть подготовлены:
- секрет `/etc/keril.art/counter-secret` (64 hex-символа, `root:www-data`,
  права `0640`);
- папка данных `/var/lib/keril.art/counter` (владелец `www-data`, `0750`);
- в server-блоке nginx на `127.0.0.1:8444` — обработка `/counter.php`
  через `php8.5-fpm.sock` и строка `error_page 404 /404.html;`;
- кэш (настроил Claude на сервере по просьбе владельца, снаружи проверено
  2026-11-12): HTML (`/`, `*.html` и страница 404 на любом адресе) —
  `Cache-Control: no-cache`, браузер каждый раз сверяет страницу по ETag
  (304, если не менялась), так что выложенная версия видна сразу;
  `og-image.jpg` — тоже `no-cache`; `monocraft.woff2`, `favicon.ico`,
  `apple-touch-icon.png`, CSS/JS/картинки — `max-age=604800` (7 дней);
  `counter.php` — свой `no-store`. В конфиге: `location ~ \.html$` с
  `add_header Cache-Control "no-cache" always` (только он доходит и до
  ответа 404; `expires` на ошибки не действует) и повторно подключённым
  сниппетом заголовков безопасности — иначе `add_header` в `location`
  отменил бы HSTS и CSP уровня server; `location = /og-image.jpg` с
  `expires epoch`; статика — `expires 7d`. Заголовки безопасности на всех
  ответах на месте. Справочный `deploy/nginx/keril.art.conf` повторяет
  эту схему (переписан 12.11.2026 под новый сервер), но рабочим
  конфигом не является;
- для Cloudflare Turnstile — секретный ключ виджета в
  `/etc/keril.art/turnstile-secret` (`root:www-data`, `0640`). Без этого
  файла `counter.php` считает визиты без проверки Turnstile.

### Защита (что где)
- `index.html`: CSP через `<meta>`, работает без правок nginx. В
  `connect-src` разрешены `https://api.github.com` (список проектов) и
  `https://api.mymemory.translated.net` (перевод описаний). nginx шлёт
  ещё и свой заголовок `Content-Security-Policy` (`base-uri`, `object-src`,
  `frame-ancestors`, `upgrade-insecure-requests` — то, что `<meta>` не
  умеет); браузер применяет обе политики сразу. Если в заголовок nginx
  когда-нибудь добавят `script-src`, `connect-src` или `font-src`, туда
  нужно вписать те же адреса, иначе скрипты, список проектов, перевод
  или шрифт перестанут грузиться.
- `'unsafe-inline'` в `script-src` оставлен сознательно (решение владельца
  12.11.2026): хэши inline-скриптов вместо него устаревали бы после каждой
  правки скрипта и выключали бы весь JS на сайте, а места для внедрения
  чужого кода нет — всё внешнее (GitHub, перевод) выводится только через
  `textContent`, `innerHTML` берёт лишь постоянные иконки. Не менять без
  просьбы владельца.
- `/.well-known/security.txt` (RFC 9116): куда писать о найденной
  уязвимости — только `hello@keril.art`. Источник в репозитории —
  `landing_page/.well-known/security.txt`. На сервере файл создан
  13.11.2026 и совпадает с репозиторием (`keril-deploy` может его
  перезаписывать). Строку `Expires` нужно обновлять раз в год, до
  12.11.2027 (новая дата не дальше года вперёд), и выкладывать как остальные
  файлы: `scp -o BatchMode=yes E:\keril.art\landing_page\.well-known\security.txt keril-deploy:/.well-known/security.txt`.
- TLS (проверено снаружи 13.11.2026): на `127.0.0.1:8444` nginx принимает
  TLS 1.2 и 1.3 с наборами шифров Mozilla intermediate (TLS 1.2 — для
  старых устройств), заголовок `Cross-Origin-Opener-Policy: same-origin`
  на сайте и на HTML (`snippets/keril-coop.conf`, подключён и в блоке
  server, и в `location ~ \.html$`, где свой `add_header`).
- `robots.txt` запрещает честным ботам трогать `counter.php`.
- `counter.php`: защита от ботов и накрутки (см. ниже), тоже работает без
  правок nginx.
- `deploy/nginx/keril.art.conf` — только справочный пример server-блока
  на `127.0.0.1:8444` под новый сервер: `ssl proxy_protocol`, `http2 on`,
  `real_ip` из PROXY-заголовка Xray, сниппет заголовков безопасности,
  только GET/HEAD/POST, исполняется только `counter.php` (PHP 8.5) с
  лимитом 30 запросов в минуту с IP, скрытые файлы — 404 (кроме
  `.well-known`), кэш как описано выше. Имена зон и список расширений
  в нём примерные; рабочий конфиг и его описание
  (`E:\PersonalServer\SITE-SERVER-NOTES.md`) — у владельца.

### Счётчик и cookie
Внизу сайта баннер "cookies.exe" (`#cookie-banner`, общий с окошком
класс всплывающего XP-окна `.xp-popup`) с кнопками
"Принять"/"Отказаться"; выбор хранится в `localStorage`
(`keril-art-cookies`), изменить его можно ссылкой "настройки cookie"
(`#cookie-settings`, класс `.footer-link` в ряду `.footer-links` под подписью). Пока выбора нет или выбран отказ, сайт только
читает статистику (`GET counter.php`) — cookie не ставится, визит не
считается. После "Принять" — `POST counter.php` с заголовком
`X-Keril-Counter: 1`. Отказ после согласия — `POST counter.php?action=forget`:
запись этого браузера удаляется, cookie стирается.
Текст баннера (`cookieText`) кроме cookie и Turnstile честно называет
остальные сервисы, к которым обращается браузер посетителя: список
проектов приходит с GitHub API, описания переводит MyMemory (оба — без
cookie, `credentials:'omit'`, только при открытии проектов или поиска).
Если сайт начнёт обращаться к новому стороннему сервису, дописать и его.

Как `counter.php` защищается от ботов и накрутки:
- визит засчитывается только когда браузер вернул cookie из прошлого
  ответа (первый POST ставит cookie и отвечает `needsConfirmation`,
  страница сразу повторяет запрос) — клиенты без cookie не считаются;
- запись только POST'ом с заголовком `X-Keril-Counter: 1` и, если браузер
  их прислал, с совпадающими `Origin` и `Sec-Fetch-Site: same-origin`,
  иначе 403; другие методы — 405;
- User-Agent с признаками ботов/скриптов (bot, crawl, headless, curl,
  python и т.п.) или пустой — не считается (сам UA не сохраняется);
- список не растёт больше 500 000 записей (`KERIL_COUNTER_MAX_VISITORS`);
- Cloudflare Turnstile (невидимый виджет): после "Принять" страница
  грузит скрипт `challenges.cloudflare.com` (до согласия — никогда),
  получает одноразовый токен с `action: 'visit'` и шлёт его в заголовке
  `X-Keril-Turnstile` (в теле нельзя: nginx пускает тело до 1 КБ, токен
  длиннее). `counter.php` проверяет токен через `siteverify` (success,
  action, hostname) только на том запросе, который считает визит, только
  для браузера, которого ещё нет в списке (вернувшийся прошёл проверку,
  когда его засчитали впервые, — для него Cloudflare не спрашивается), и
  до блокировки файла (список для этого читается без блокировки — он
  заменяется атомарно). Публичный ключ — константа `TURNSTILE_SITE_KEY` в
  `index.html`, секрет — `/etc/keril.art/turnstile-secret`
  (`KERIL_TURNSTILE_SECRET_FILE`). Ключи нужны оба: только секрет — никто
  не засчитывается, только публичный ключ — токен игнорируется. Если
  Turnstile не загрузился, не ответил за 10 с или выдал ошибку (Cloudflare
  в России часто замедлен у провайдеров), страница шлёт POST без токена с
  заголовком `X-Keril-Turnstile-Status: unavailable`. Тогда `counter.php`
  засчитывает нового посетителя только в пределах суточной квоты его
  адреса: не больше 3 новых в сутки с одного IP
  (`KERIL_COUNTER_MAX_UNVERIFIED_PER_IP`, 0 выключает запасной путь;
  `takeUnverifiedPlace`, под блокировкой). Так российские посетители
  считаются, а накрутить счётчик из одного адреса нельзя (IP настоящий:
  nginx восстанавливает его из PROXY-заголовка Xray). Без этого заголовка
  и без токена — не засчитывается. Цифры всё равно показываются (страница
  сначала читает их GET-запросом). Новая страница работает и со старым
  `counter.php` (лишний заголовок он игнорирует), и наоборот. Если пока
  страница ждала токен, посетитель отказался от cookie, визит не
  отправляется (согласие проверяется ещё раз после получения токена). CSP страницы
  разрешает `challenges.cloudflare.com` в `script-src` и `frame-src`.
- Turnstile тяжёлый: около полсекунды его iframe снимает отпечаток браузера
  и видеокарты (читает пиксели canvas), и страница на это время
  подтормаживает — это был "статтер через полсекунды после захода". Поэтому:
  визит засчитывается раз в сутки (как и на сервере), и после засчитанного
  визита страница запоминает дату (UTC) в `localStorage` (`keril-art-counted`)
  и до следующих суток не запускает Turnstile и не шлёт POST — только
  читает цифры GET-запросом. В первый заход за день Turnstile стартует не
  раньше 2.5с после открытия (`turnstileStartAfter`, когда приветствие уже
  допечатано) и когда браузер свободен (`requestIdleCallback`,
  `waitForQuietPage`). Посетитель, ушедший раньше, не засчитывается. Отказ
  от cookie стирает и эту отметку.

Хранение: `all-visitors.jsonl` в `/var/lib/keril.art/counter/` — по одной
строке на браузер (постоянный HMAC-хэш cookie, даты первого и последнего
визита). Файл перезаписывается не чаще раза в день на браузер через
`.tmp` + атомарный `rename` под блокировкой `all-visitors.lock`.
Статистика для GET берётся из маленького `stats-cache.json`, который
обновляется раз в день или при изменении списка. Ответ: уникальные
браузеры за всё время (`uniqueVisitorsAllTime`) и за последние 30 и
365 дней (`uniqueVisitorsPastMonth`/`PastYear`): браузер входит в
период, если последний визит попадает в него. Дневные журналы
просмотров прошлых версий больше не пишутся и удаляются через 90 дней.
User-Agent и Referer не сохраняются; cookie случайная,
HttpOnly/Secure/SameSite=Strict, в файлах только её HMAC-хэш. IP-адрес
хранится только для квоты визитов без Turnstile и только как HMAC с
секретом счётчика (вместе с датой) в `unverified-ГГГГ-ММ-ДД.json`, не больше
10 000 адресов в сутки; файлы прошлых дней удаляются в конце каждого
POST-визита. Баннер cookie об этом предупреждает ("сервер вместо этого
может до конца суток хранить хэш вашего IP-адреса").

### Шрифт
Monocraft 4.2.1 лежит на нашем сервере: `monocraft.woff2` (31 КБ) рядом с
`index.html`, в репозитории тоже. Раньше грузился с jsDelivr, но этот CDN у
части провайдеров в России блокируют — тогда сайт открывался обычным
моноширинным шрифтом. WOFF2 сделан из оригинального TTF без изменения
глифов (fontTools, `flavor='woff2'`); в метаданные (name ID 13/14)
дописана ссылка на лицензию SIL OFL 1.1 — у шрифта нет зарезервированного
имени, так что так можно; копирайт автора остаётся в файле и в комментарии
у `@font-face`. CSP: `font-src 'self'`. В `index.html` адрес относительный
(`monocraft.woff2`), в `404.html` — абсолютный (`/monocraft.woff2`), потому
что 404 открывается по любому пути.
`<link rel="preload">` в `<head>` (и в `404.html`) начинает загрузку сразу,
а не когда браузер дойдёт до первого текста, поэтому текст меньше
"прыгает" при смене шрифта на первом заходе. Адрес в preload и в
`@font-face` должен совпадать.

### Анимации внутри колонки окон
Звёздочки (`.twinkle`: две у приветствия, сердечко у счётчика, две у
подписи) мерцают только прозрачностью. Раньше они ещё и меняли размер
(`transform:scale`), и неподвижная открытая страница пересчитывала стили
каждый кадр — 165 раз в секунду, ~3% ядра процессора (замер 12.11.2026,
`Performance.getMetrics`: `RecalcStyleCount`). Причина: Chromium не отдаёт
видеокарте анимацию размера или положения внутри элемента с `zoom`, а у
`.page-column` есть `zoom:var(--ui-scale)` (даже `scale` и `steps()` не
помогают). Прозрачность считается на видеокарте: теперь 0 пересчётов.
Поэтому внутри `.page-column` и `.xp-popup` бесконечно анимировать можно
только `opacity`; облака фона (`transform`) — вне колонки, им можно.
Короткие анимации (окно гаснет и возвращается, баннер выезжает) не мешают.

### Аудит (ноябрь 2026) и ложные тревоги
Проверено на живом сайте: ответ сервера ~70 мс, первая отрисовка 0.1–0.4 с,
на главной три запроса (HTML 119 КБ → 40 КБ gzip, шрифт, счётчик), long
tasks нет, CLS 0.0005 (компьютер) и 0.001 (телефон); ошибок консоли нет ни
на одной странице в обеих темах и языках на 1366/390/320 px; горизонтальной
прокрутки нет; axe — 0 нарушений. Что инструменты показывают зря (не
"чинить"):
- валидатор W3C: `paint-order` "не существует" (его CSS-проверка устарела,
  свойство поддерживают все браузеры); `role="combobox"` у `input
  type=search` (ARIA in HTML это разрешает, axe тоже; `type=text` убрал бы
  кнопку "Найти" на клавиатуре телефона); "aria-hidden не нужен при
  hidden" (элементы показываются скриптом, `aria-hidden` нужен); "section
  без заголовка" у баннера cookie (заголовок — `span` намеренно);
- axe `color-contrast` на подписи и "настройки cookie" в тёмной теме — белый
  текст с чёрной обводкой, контраст axe с обводкой не считает;
- проверка "элементы шире окна" цепляет облака фона: они плывут за краем
  внутри `position:fixed` слоя, прокрутки это не создаёт.

### Как проверить локально
PHP и nginx на этой машине не установлены; для проверок использовались
официальные сборки во временной папке: `php -S` (или `php-cgi -b`) с
переменными `KERIL_COUNTER_SECRET_FILE` и `KERIL_COUNTER_DATA_DIR`,
указывающими на тестовые секрет и папку, и `nginx -t` для конфига.
Страницу проверяли через Playwright (Python, во временном venv) в
установленном Microsoft Edge (`channel='msedge'`, браузер не скачивается),
с настоящей CSP страницы; ответы GitHub API подменялись через
`context.route`. Для попиксельного сравнения вёрстки до/после правок
фон `.scene` скрывается, анимации отключаются. Подтормаживания искали
замером кадров (`requestAnimationFrame`), long tasks и long-animation-frame
и трассировкой Chrome (`browser.start_tracing`) на настоящем домене: в
Playwright документ `https://keril.art/` подменялся локальным `index.html`,
остальное (шрифт, счётчик, Turnstile) шло по-настоящему; headless-браузер
счётчик не засчитывает (User-Agent).
Мелочи, на которых уже спотыкались: обработчик `context.route` — функция
одного аргумента (`lambda route: ...`), иначе Playwright подставит второй;
тему, язык и согласие задавать через `context.add_init_script`
(`keril-art-cookies`='declined', чтобы тест не считался визитом); полосы
прокрутки Playwright прячет, для их проверки
`launch(ignore_default_args=['--hide-scrollbars'])`; превью ссылки —
скачать страницу с User-Agent `TelegramBot (like TwitterBot)` и разобрать
`og:*`.

Не делать (решено): английские Open Graph (у языков нет отдельных адресов),
sitemap (одна страница), HSTS preload/includeSubDomains (на поддомене VPN),
публичный репозиторий, правки профиля GitHub.

## Пет-проекты на поддоменах (план, не реализовано)
Каждый пет-проект — свой поддомен (`project1.keril.art` и т.п.),
свой отдельный `index.html`/набор файлов и своя папка в `/var/www/`.
Серверную часть делает владелец вместе с ассистентом (не в рамках правок
этого сайта): A-запись в Namecheap, отдельный server-блок nginx, который
тоже слушает `127.0.0.1:8444 ssl proxy_protocol` (nginx выбирает
сертификат по SNI; в `serverNames` Reality-инбаунда новое имя добавлять не
нужно — Xray передаёт nginx любой обычный HTTPS-запрос, так уже работает
`vpn.keril.art`), и
сертификат через `certbot --webroot`. Общий стиль (палитра, шрифты,
XP-кнопки) стоит унести в происходящий от этого файла шаблон, когда
появится второй проект — но пока рано абстрагировать, делай каждый
поддомен отдельным файлом.
